```
## 2. 分类算法

分类是有监督学习的核心任务。它从带标签的训练样本中学习决策边界，再对新样本预测类别。模型选型要考虑特征维度、样本规模、可解释性要求以及推理延迟预算。在工业场景中，逻辑回归与梯度提升树仍然是表格数据的强基线，深度模型更适合图像、文本等非结构化输入。当特征以数值型和低基数类别型为主时，树模型往往优于线性模型；当特征维度极高且稀疏时，线性模型配合正则化更加稳定。除此以外，还要关注样本不均衡问题，必要时采用过采样、欠采样或代价敏感学习来修正决策边界偏移。
```

```
### 1.2 定义中的四个关键词（缺一不可）

Fayyad 定义里的四个形容词，恰好构成判断"这是不是数据挖掘"的检验清单：

- **有效（valid）**：模式在**未见过的数据**上仍然成立，不是样本噪声或偶然巧合。这是防过拟合的根本要求。
- **新颖（novel）**：不是显而易见的事实，也不是业务方早已知道的常识。用 SQL 分组统计就能得到的结论，不算挖掘结果。
- **潜在有用（potentially useful）**：能改变某个决策、降低某类成本、提升某项指标。不能导向行动的"洞察"只是谈资。
- **可理解（ultimately understandable）**：人能够理解并据以行动。可解释性不是锦上添花，而是知识能否被采纳的前提（风控、医疗、司法等高风险场景尤其如此）。

再加上一个隐含前缀：**非平凡（nontrivial）**——需要搜索、迭代、建模，而不是一次查询。
```

```
### 1.3 数据挖掘不等于"从数据库里查东西"

这是初学者最常踩的认知坑。区别在于信息是否**显式存在**：

| 类型 | 问题 | 结果性质 |
|---|---|---|
| 数据库查询 | "上季度华东区销售额是多少？" | 事实**已在**数据中，只是取出来 |
| OLAP / 多维分析 | "按产品线下钻看各月销售额变化" | 事实**已在**数据中，换视角汇总 |
| 数据挖掘 | "哪些商品组合被一起购买的概率显著高于随机？" / "哪些客户未来 90 天最可能流失？" | 模式**不在**数据中显式存在，需算法推断 |
```

```
### 1.4 数据挖掘能做什么、不能做什么

**能做**：在海量变量中筛出与目标相关的因素；给出可量化的预测与排序；发现人眼难以察觉的分组、关联、异常；把经验规则变成可复现的模型。

**不能做**：

- 不能**无中生有**——数据里没有的信息，算法造不出来（缺失关键变量时，再复杂的模型也无效）。
- 不能**自动给出因果结论**——模型学到的是相关性，因果需要实验设计或因果推断方法。
- 不能**替代业务判断**——它输出概率与排序，取舍与代价权衡仍由人决定。
- 不能**自动清理脏数据**——数据质量问题的识别往往比建模更耗人力。
```
